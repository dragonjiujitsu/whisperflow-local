Concurrency

Three lanes so the UI never freezes.

Audio capture, heavy inference, and the overlay each live on their own thread. Every cross-thread touch is marshalled through queued Qt signals — widgets are only ever touched on the main thread.

Thread A
Audio callback
PortAudio frames → ring buffer → RMS queue ⇢ signal
Thread B
STT + cleanup worker
faster-whisper → Ollama cleanup → focus-safe insert ⇢ signal
Thread C
Qt main / UI
state machine → overlay pill → tray icon fail flash · cues
hotkey & audio callbacks never touch a widget directly — they emit, the UI thread reacts.
Life of a word

From your breath to the page.

Follow one sentence all the way through. Each step is tagged with the thread it runs on — so you can see what's happening in parallel.

1
UI thread

You tap Ctrl+Win

A global key-listener catches the tap and drops a message to the UI thread. The state machine flips idle → recording; the start-cue sounds and the waveform pill fades in.

2
Audio thread

You start speaking

Your microphone streams sound. The audio thread wakes every few milliseconds and receives a tiny chunk — 16,000 samples per second, mono. This thread runs on a strict clock: if it ever pauses, audio drops.

3
Audio thread

Each chunk is parked — fast

For every chunk it does two cheap things only: measure loudness (for the pill) and copy the raw samples into one big pre-reserved buffer. No AI here — the heavy work waits, so capture never stutters.

4
UI thread

The pill breathes with your voice

Thirty times a second the UI thread reads those loudness values and animates the ink-thread waveform. That live reaction is the only thing on screen — and it never blocks anything.

5
UI thread

You tap again to finish

State flips recording → processing. Crucially, it snapshots which field had focus right now — that's the destination for the paste. Recording stops, the whole buffer is handed to a fresh worker thread, and the pill hides.

6
Worker thread

Transcribe — on your GPU

The audio goes to faster-whisper (large-v3-turbo) on CUDA. The neural net turns sound into raw text; confidence checks throw out silence and hallucinations.

measured: ~95–430 ms — even for 40+ seconds of speech
7
Worker thread

Clean up — local LLM

The raw transcript goes to a local Ollama model with one instruction: strip filler, fix grammar, keep the speaker's voice. It stays warm between dictations so it answers instantly.

raw transcript
"um so like i was thinking we could uh ship it tomorrow"
"I was thinking we could ship it tomorrow."
cleaned · meaning & tone preserved
measured: ~260–790 ms warm
8
Worker thread

Insert — into the right field

It re-checks the field from step 5 still has focus. If yes: save your clipboard, place the cleaned text, fire Ctrl+V, restore your clipboard. If you wandered off, it aborts and parks the text on the clipboard instead of pasting into the wrong place. Then: back to idle.

measured: ~165 ms · total journey ≈ 0.55–1.3 s

Design decisions

Opinions, with their tradeoffs named.

i

Runtime is 100% local

Cleanup runs on a local Ollama model; cloud Haiku was explicitly ruled out. Only the one-time setup download touches the network.

cost — you host the models & the VRAM, in exchange for true privacy
ii

Toggle, not hold-to-talk

Tap to start, tap to finish. Easier on the hands for long dictation; an auto-finalize at five minutes guards a forgotten session.

cost — needs a visible recording cue: the overlay pill
iii

Paste, with focus re-verified

Clipboard paste is instant block-insert. Focus is captured at stop and re-checked before paste — if you've moved, it aborts and stashes the text instead of leaking it.

cost — a type() fallback for paste-hostile apps
iv

A non-activating overlay

The waveform pill is always-on-top yet never steals focus and passes clicks straight through — so paste still lands in your text field.

how — WS_EX_NOACTIVATE | WS_EX_TRANSPARENT on the HWND
